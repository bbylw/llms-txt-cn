## 为何选择 Markdown 而非 XML

当前语言模型最广泛且最容易准确理解的文本格式就是 Markdown。仅需明确指出关键 Markdown 文档的位置，就已经迈出了极有价值的第一步；而提供清晰的基础结构，则能进一步帮助语言模型迅速判断应当从何处获取所需信息。

`llms.txt` 的独特之处在于：它选择使用 Markdown 来组织结构化信息，而不是 XML 或 JSON 等传统纯数据格式。这是因为这些文件的主要消费方是语言模型与 AI 智能体；与此同时，`llms.txt` 依然遵循一套严格且确定的格式约定，因此完全可以使用传统程序化工具（如正则与轻量解析器）进行可靠读取。

## 路径作用域与优先级

`llms.txt` 规范适用于名为 `llms.txt` 的文件，可以放置在网站根路径 `/llms.txt` 或任意子路径下（例如 `/docs/llms.txt`）：

- 一个 `llms.txt` 文件覆盖其所在路径之下的所有 URL。
- 当某个页面同时被多个层级（例如 `/llms.txt` 与 `/docs/llms.txt`）覆盖时，智能体应当使用**路径最具体**的那一份。

## 严格五段式顺序规范

遵循本规范的 `llms.txt` 文件，必须**按照以下特定顺序**由 Markdown 区块组成：

1. **可选的字节顺序标记（BOM）**
2. **一个一级标题（H1）**：写明项目或网站名称。这是整个文件中**唯一必填**的区块。
3. **一个引用块（Blockquote）**：包含项目的简短摘要，写明理解文件其余部分所需的关键背景信息。
4. **零个或多个任意类型的 Markdown 说明区块（标题除外）**：例如普通段落、无序列表等，用于补充关于项目的详细说明或如何解读所提供文件的提示。
5. **零个或多个以二级标题（H2）分隔的「文件列表」区块**：指向可获取更多详细信息的 URL 列表。
   - 每个「文件列表」均为标准的 Markdown 无序列表。
   - 每一列表项必须包含一个 Markdown 超链接 `[name](url)`，随后可选地附带一个英文冒号 `:` 与关于该文件的说明文字。

<Aside type="caution" title="注意第 4 区块不能使用标题">
  在 H1 与引用块之后的补充说明区域中，切勿插入 H2 或其他级别标题。一旦出现 `##` 二级标题，解析器就会将其识别为「文件列表」分组的起始标记。
</Aside>

## 标准结构模板

```markdown
# Title

> Optional description goes here

Optional details go here

## Section name

- [Link title](https://link_url): Optional link details

## Optional

- [Link title](https://link_url)
```

## 关于 `Optional` 区块的约定

名为 `## Optional` 的二级标题分组按惯例用于存放**次要信息**：当智能体需要更精简的上下文时，可以安全跳过该分组中的链接。

在 v2 规范中，由于移除了早期的 `llms_txt2ctx` 机械展开工具，`Optional` 不再带有强制的机械处理语义，但它依然是区分「核心必读资源」与「延伸参考资料」的最佳实践约定。
