在 Answer.AI 官方仓库中，[`ed.qmd`](https://github.com/AnswerDotAI/llms-txt/blob/main/nbs/ed.qmd)（官网 [`ed.html`](https://llmstxt.org/ed.html)）用一段颇具极客幽默感的虚构演示，说明了哪怕是最古老、最极简的经典 Unix 行编辑器 [`ed`](https://www.gnu.org/fun/jokes/ed-msg.html)，在接入 `llms.txt` 后也能变成高效的 AI 编程助手。

下面还原了这段完整的交互流程，帮助你直观理解现代 IDE（如 VS Code、Cursor、Vim、Emacs）与命令行助手是如何利用 `llms.txt` 的。

## 从开启提示与加载文档索引开始

首先，用户启动 `ed`，并输入 `H` 开启友好报错信息提示（“当然，真正的 `ed` 老手显然不需要友好提示”），随后使用假设扩展的 `L`（load）命令从 `fastht.ml/docs` 获取并加载 `llms.txt` 上下文：

```sh
$ ed
* H
* L fastht.ml/docs
Checking for /llms.txt at fastht.ml/docs...
Found /llms.txt. Parsing...
Fetching URLs from "Docs" section...  Fetching URLs from "Examples" section...
Skipping "Optional" section for brevity.
Creating XML-based context for Claude...  Context created and loaded.
```

如果目标站点没有 `llms.txt`，编辑器则不得不退回到传统的 HTML 爬虫解析方式；而有了 `llms.txt` 后，`ed` 只需解析索引、抓取核心文档与示例链接（按配置跳过 `Optional` 以保持精简），即可组装好上下文，全程保持 `ed` 一贯的沉静克制，仅输出简明的状态提示。

## 借助上下文生成应用代码

接下来，用户输入假设的 `x`（eXecute AI）命令，指令 AI 结合刚才加载的 `llms.txt` 上下文创建一个最简单的 FastHTML 应用：

```sh
* x 创建一个在 <div> 中输出 'Hello, World!' 的极简 FastHTML 应用。
正在分析上下文与指令...
正在生成 FastHTML 应用代码...
已将生成的应用写入缓冲区。
```

由于 `llms.txt` 中明确给出了 FastHTML 与 Starlette、HTMX 的惯用模式以及常见差异提示，模型不会幻觉出过时或不兼容的语法，而是直接输出地道的 FastHTML 写法。

## 查看并保存最终文件

随后，用户查看缓冲区中的总行数（`n`）并打印文件内容（`p`），可以看到仅用 5 行代码就完成了一个可运行的服务端应用：

```sh
* n
5
* p
from fasthtml.common import *
app,rt = fast_app()
@rt
def index(): return div("Hello, World!")
serve()
```

最后，用户将代码写入 `hello_world.py` 并退出编辑器（`q`）：

```sh
* w hello_world.py
5
* q
```

这正是 `llms.txt` 设计初衷的缩影：不需要把整座文档站塞进编辑器，只需让工具顺着简洁清晰的索引获取当前任务真正需要的专业知识。
